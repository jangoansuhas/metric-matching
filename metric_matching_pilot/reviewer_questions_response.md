# Response to six reviewer questions (development status, 2026-09-29)

The following answers distinguish pinned public development observations from a future independently judged public study. A blank field is not a zero result.

| Question | What the current evidence supports | What remains |
| --- | --- | --- |
| 1. Held-out size and compilation | The first two hash-ranked pinned repositories passed the source eligibility screen: at least **2** and **3** SQL aggregate outputs, respectively. These are lower bounds, not complete metric or pair denominators. Rank 1 parsed with **0 declared MetricFlow metrics** and 0 generated metric queries; rank 2's frozen adapter exited before parse on a nested `transform/dbt_project.yml` layout. Neither gives a declared-metric compilation fraction. Jaffle development has 19 declared metrics and 171 unordered pairs, with MetricFlow SQL for all 19 in a same-commit DuckDB build (18 ungrouped and one requiring `metric_time`), but that cannot substitute for held-out coverage. | Freeze source-defined numeric output inventories, unsupported statuses and complete pair frames for both selected projects. Distinguish source output coverage, adapter targets, parse success, and generated metric-query success with explicit denominators. |
| 2. Permissive AST equivalence | A separately versioned aggressive baseline, under pinned SQLGlot 30.20.0, asserts `direct_equivalent` for **one** pair (`cumulative_revenue`/`revenue`) from identical ungrouped generated ASTs modulo alias; it abstains on **170/171**. This is a *deliberately permissive full-metric assertion inferred from an ungrouped query*. On the bounded month request, generated MetricFlow queries return **$15,670 versus $19,422** for October 2024, refuting extension of that assertion to month grain. It does **not** refute a claim explicitly limited to the ungrouped scalar. This is development evidence, not a gold-scored error rate. | In a held-out study, freeze each baseline's natural assertion scope, then count unsafe assertions only against sufficient adjudicated reference evidence or aligned observed counterexamples. |
| 3. Executed counterexamples | The pinned public-seed scalar `$637,444` versus `$240,877` and aligned day/order differences refute `revenue`=`food_revenue` at those scopes; the bounded month values refute `revenue`=`cumulative_revenue` at month grain. The **483** zero-item orders make a declared derived order expression `NULL` where a *hypothetical* zero-filled expression would be `0`, but show **no mismatch** between the two actually compared gross-profit formulations; their scalar and 365 day values reconcile. See `counterexample_decision_audit.md`. | A witnessed difference is a **scoped refutation of equivalence** only when inputs, grain, time, population and NULL/value semantics align. It does not automatically establish a positive relationship class, while finite equality cannot prove universal identity. |
| 4. Mask guard coverage | On the pinned Jaffle 171-pair development packet, the structural conditional-mask signal fires for **2 pairs without** the description guard and **2 with** it (`food_revenue`/`revenue`, `drink_revenue`/`revenue`). The guarded rule currently hardcodes affirmative food/drink wording. | Outside Jaffle, firing rate and error rate are **unknown**; the two selected sources were screened only for eligibility and adapter coverage, with no pair method run. The current two outputs do not establish portability or superiority over the independent mask-aware AST comparator, which ties them. |
| 5. Human agreement | **Not estimable.** The development practice submissions are not a verified, independently adjudicated two-human gold set. AI implementation reviews are not human labels. | Have two qualified people separately label the same prediction-free selected pairs; preserve originals, use a distinct adjudicator on disagreements and fixed agreement audit, and report a confusion matrix, raw agreement and a chance-adjusted statistic only when class counts permit. |
| 6. Cumulative month semantics | [dbt's v1.12 cumulative-metric documentation](https://docs.getdbt.com/docs/build/cumulative?version=1.12) explicitly says `period_agg` defaults to **`first`** for coarser requested granularity. The pinned Jaffle metric omits `period_agg`; the semantic manifest records `first`, and the generated monthly SQL uses `FIRST_VALUE` over daily rows. In the bounded reconstruction, each observed month has first-of-month items, so October's **$15,670** is the cumulative value **through October 1**, not the month-end $34,640 control. That particular first-calendar-day value depends on the query's surviving joined rows; the documented default is first value of the period. | Practitioner misreading frequency is **unknown**: no survey, usage trace or blinded review outcome measured it. See `metricflow_time_semantics_note.md`. |

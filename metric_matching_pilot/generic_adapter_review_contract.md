# Independent review contract: generic SQL aggregate inventory adapter

Development-only gate, fixed before reviewing `generic_sql_inventory.py`. Review the adapter and already inspected development fixtures only. This is an implementation and comparison audit, not human gold, matching accuracy, or a novelty claim. A failed item fails the gate; record evidence and the narrowest reason in the appended independent review.

| Gate | Pass condition | Fail condition |
| --- | --- | --- |
| Generic input and provenance | Accept a pinned project/version and SQL source or real compiled artifact without project-specific names. Each card identifies the source path and lines, SQL dialect or parser version, immutable source hash, and compiled path/hash and source-to-compiled mapping **only when actually verified**. Distinguish raw SQL from compiled SQL and absent compilation. | GTM/fixture-specific dispatch, a fabricated compiled location, mutable `HEAD` as evidence, or a raw-source hash represented as compiled provenance. |
| Complete universe | Deterministically list every in-scope numeric scalar/aggregate definition with stable IDs, including failed or unsupported extractions; enumerate each unordered within-project pair exactly once (`N(N−1)/2`). Keep exclusions and reasons explicit. | Selecting only easy, parsed, matching, or promising metrics; dropping unsupported cards/pairs; duplicate, missing, or outcome-dependent pairs. |
| Parse and coverage | Report total definitions and pairs, successfully parsed, unsupported syntax, parse failures, and missing decisive evidence separately, with reproducible reasons and locations. Unsupported cases remain `needs_review`/abstain. SQL AST normalization is syntax evidence only. | Missingness silently becomes a match, a negative, or an omitted denominator; a parser failure is concealed. |
| Aggregate and NULL semantics | Preserve `SUM` versus `MEDIAN` (also count/distinct where present), raw versus already rounded aggregation, SQL `NULL`, absent groups, outer joins, and explicit `COALESCE` with its fill value. An equivalence or rollup suggestion with an unverified decisive rule stays conditional/needs review. | SUM/MEDIAN conflation; `NULL` treated as zero or missing row as present without source-backed transformation; ordinary equality on nullable values claimed to prove equality. |
| Joins and time | Carry join keys/type and unresolved cardinality/fanout, grouping keys/grain, filters, actual date predicate and time key, window boundaries/timezone, and snapshot alignment. Keep row-preservation and unassigned-row rules unknown until evidenced. A constant period label alone never proves a bounded source window. | Join fanout hidden, native grain or filter lost, date label promoted to a filter, or conditional cross-grain assertion with unknown prerequisites promoted to direct equivalence. |
| Label separation | Recursively reject or strip gold labels, prior decisions, row outcomes, reconciliation totals and adjudicated prerequisites from decision inputs; preserve a digest of label-free input bytes. Results remain hypotheses requiring review. | Any outcome-bearing field can affect extraction, ranking, classification or candidate inclusion. |
| Same-input comparators | Freeze one versioned `I1` packet and full pair ID list for normalized SQL/lineage, SQL AST, constraint-aware, and proposed decision paths. Give each the identical source/compiled context and check budget; record versions, parser dialects, thresholds, abstentions, runtime and coverage. Run classifiers on fixed pairs independent of retriever output. Keep `I0` name-only separate. | Exclusive curated fields or oracle prerequisites for one method; different candidate universes or hidden source access; tuning on held-out cases. |
| Prospective boundary | Limit checks to the existing development fixtures, including `sql/metric_views.sql` for alias, scope, fanout and unrelated-count controls, plus controlled NULL/COALESCE and SUM/MEDIAN cases. Freeze code/config and record hashes before any held-out source access. | Opening new held-out repository source for this review, selecting favorable test cases, or calling development controls independent human evidence. |

Review evidence to append after the file appears: inspected adapter path/hash; read-only or temporary-output commands and observed exit codes; card/pair counts and coverage breakdown; at least one concrete positive and negative boundary check; same-input packet digest and comparator pair-set equality; unresolved risks. Do not alter worker code. Exact retrieval recall and unsafe-assertion rates remain unavailable without complete, independently human-adjudicated target universes under `evaluation_contract.md`.

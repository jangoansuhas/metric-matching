# Public study pre-source policy (development planning)

Date: September 29, 2026. This is an author-side policy for a public-repository
Industrial Track study. It does not select a repository, open a new held-out
source tree, create human gold, or amend the original blank calibration packet.
The existing complete, dated metadata-only search frame and fixed generic
adapter remain necessary inputs, not evidence that the evaluation is ready.

## Eligibility and coverage

The primary pair task concerns declared or reproducibly extracted numeric
scalar outputs at a recorded group/time scope. A generated query, a numeric
aggregate declaration, and an observed runtime numeric value are different
forms of evidence. The development gate's `eligible_declaration_only` status
is an extraction signal; `unknown` is neither an exclusion nor a negative
relationship label. Derived, ratio, cumulative, templated, and unsupported
definitions remain in a complete exposed-definition inventory, with reason,
source span and extraction outcome. A predeclared eligibility screen
must be fixed before any held-out code is opened, then applied without seeing
method ranks or apparent positive matches. If a definition's numeric-scalar
status remains unresolved, keep it visible in coverage and annotation-work
counts. Do not silently discard any pair containing it.

For exact within-project Recall@k, the evaluated anchor universe must have
resolved eligibility and relationship/conditional-target status for **every**
other exposed candidate, including parse failures and low-ranked items.
Unresolved candidates cannot be counted as negatives. If the cost of resolving
them is beyond the prespecified budget, report judged-pool retrieval and
unresolved coverage, not exact Recall@k. The study must distinguish a
declaration-level numeric screen from runtime certification and record the
denominators at each stage.

## Fair method comparison

On each selected project, build one immutable, versioned I1 source packet and
one complete pair-ID frame before methods run. Give AST/lineage, constraint
aware, proposed, and any LLM comparator the same cards, compiled evidence
where available, execution-check and human-review budget, and candidate
universe. Preserve parse/build failures as abstentions or coverage outcomes.
Record actual token, runtime and review cost. Keep I0 name-only comparators
as a limited-input tier, never a substitute for the strongest I1 comparator.
For classification, all I1 methods receive the identical adjudicated pair
sample; for retrieval, they rank the same full eligible universe.

An LLM comparator is contingent on an accessible model and a reproducible
version, prompt, context-packing procedure, temperature, token budget,
cost/latency policy, and retry rule frozen on development inputs. If these
cannot be secured before held-out source is opened, list it as unavailable and
make no comparative claim against LLM matching. Industrial relevance from
public artifacts must be demonstrated with actual maintenance tasks and
measured practitioner decisions, rather than a private-data assertion.

## Gates still open

1. Fix the source-independent numeric-scalar eligibility screen, treatment
   of raw SQL projections and time/dimension variants, fork/shared-data
   independence, and every sampling exclusion/replacement rule in a dated
   versioned protocol. A generic adapter proven on one development repository
   does not establish coverage on arbitrary public projects.
2. Commit qualified human reviewer capacity and a budget for two blind labels,
   third-person adjudication, an audit of agreements, and any complete anchor
   universes. The current practice timing is uncertain and cannot determine
   an actual held-out sample size by itself.
3. Freeze strong comparator configurations and authenticated evidence
   ingestion. A string-shaped locator, digest or verifier name is not artifact
   authenticity, nor an independently verified business meaning. No
   non-abstaining method assertion should rely on self-attestation.
4. Apply the dated metadata eligibility and hash-selection process **only
   after** those policies and the fixed generic adapter are reviewable. Do not
   inspect any new held-out repository source until then. Preserve an audit
   record of exclusions and unsupported cases without outcome-based top-ups.

After source opens, the empirical study may still find no sufficient natural
equivalence assertions or no full anchor universe. In that event report
coverage, uncertainty and failure modes descriptively; do not claim method
superiority or exact recall.

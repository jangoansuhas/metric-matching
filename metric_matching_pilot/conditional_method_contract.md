# Conditional decision development contract — September 27, 2026

This contract precedes the implementation and comparison below. It defines a **development exercise** on previously inspected public projects, not a frozen held-out evaluation, adjudicated gold set, or proof of novelty. Do not open a new project as held-out until a separate dated search-result manifest exists. Do not use selected labels, row reconciliations, owner decisions, or prior reviewers' conclusions as method inputs.

## Shared evidence packet

Generate `conditional_evidence_packet.json` from the pinned GTM branch extraction and compiled-field reports at `a71232c123a5fb78da9b52d4246950ee48591c00`, checking the compiled SQL/manifest identity and source locations. Top-level fields are `schema_version`, `provenance`, `cards` (array), and `pairs` (array). It contains exactly **11 cards** keyed by `metric_name@grain` and **55 unordered pairs**; no outcome labels. Every card must expose: `id`, `metric_name`, `grain`, `source_ref`, compiled `value_expr`, compiled `where_expr` (nullable), compiled `period_expr`, compiled `segment_expr`, compiled `group_by`, source `time_key` (nullable), sorted `value_input_fields` and `filter_input_fields`, `source_location`, `compiled_location`, `review_flags`, and `unknown_semantics` (object with keys `join_cardinality`, `null_policy`, `missing_groups`, `time_zone`, `units`, `snapshot`, `grouping_set_expansion`, each null unless independently source verified). Record pinned provenance and input hashes. Do not infer unknowns from one sample. Each pair has only `left_id` and `right_id`; algorithms must not have a hidden curated case list.

The input packet must **not** contain built-model values, reconciliations, labels, example pair IDs to favor, gold prerequisites, or prior agent judgments. Validation observations are kept in a different file and applied only *after* method outputs are committed. Scripts should read the same packet bytes and record its SHA-256.

## Same-input comparators

All methods enumerate and return an output for every pair, preserving abstentions and unsupported status. They read the exact same cards and pair list; name-only results from the prior probe are a separate `I0` limited-input reference. Comparable full-context methods use `I1` source/compiled evidence; no method gets more fields or an oracle. Output files have top-level `method`, `input_sha256`, `results` (array) and `counts`. Fixed per-pair fields: `left_id`, `right_id`, `decision` in `{direct_candidate, conditional_candidate, scope_variant_candidate, related_candidate, abstain}`, `evidence_status` in `{sufficient_for_source_candidate, needs_review}`, `conditions` (a map of named prerequisites with `verified_from_source`, `unknown`, `contradicted`, or `not_applicable` and source evidence), `reasons`, and `locations`. A candidate decision is **never** a gold relationship or an unqualified equivalence assertion.

1. **Normalized SQL/lineage baseline.** Normalize comments/whitespace and only documented harmless syntax (such as optional `AS` in a table alias) without changing string literals, predicates, numeric constants, date bounds or NULL operators. Compare normalized value/filter/period/grouping and field/ref sets. If a dimension differs, report a candidate with that difference or abstain; do not assert equivalence. Publish exactly what was normalized.
2. **Constraint-aware baseline.** Use source, value family, filter, time, grain and grouping constraints on the same packet; issue a conditional candidate only if a concrete source-supported transformation is identifiable. Unknown join cardinality, NULL behavior, missing groups, time zone, rounding and snapshot semantics must remain conditions. A different stage predicate does not become equivalent just because the value projection and lineage match.
3. **Proposed conditional explanation.** Emit a source-linked transformation and prerequisite-by-prerequisite evidence for an additive month→window rollup when supported; explicitly name zero-fill for absent month groups, `NULL` versus zero, partition coverage, segment `All` collisions, source membership, period boundaries, rounding, units and snapshot alignment. Abstain from unconditional equivalence. Nonadditive `AVG`/median/ratio operations cannot be rolled up by summing monthly outputs. Do not claim a gain over the constraint baseline unless measured under human-adjudicated conditions.

## Validation and interpretation

After outputs are fixed, check whether each method returns the same 55 pairs and disclose candidate/abstention counts and disagreements in a table. Inspect `pipeline_created@month/window` and `mql_volume@month/window` as previously known development cases, plus different-stage funnel rates and unrelated values. Compare condition lists and false-suggestion *mechanisms*, not accuracy, precision, Recall@k, or superiority. The pinned GTM built rows include an absent Enterprise September 2025 monthly pipeline group and a separately computed window total; this is a **post-output row observation**, not an input feature. The Jaffle `orders.subtotal` versus `order_items.revenue` case has 483 zero-item orders and requires an outer join and `COALESCE` at order grain; use it as an external development boundary check for NULL handling, outside the 55-pair comparator table. Do not treat a finite reconciliation as a universal proof.

## Gate to a paper result

Report unsupported syntax and manual steps. If both strong comparators and the proposed method surface the same conditions, state that there is no demonstrated incremental gain. Freeze an implementation, thresholds and fair input budgets on development projects **before** opening a new held-out repository. Then obtain two independent domain-human judgments with adjudication on complete anchor candidate universes, and measure unsafe equivalence, coverage, reviewer effort and cost by project. Private industrial claims need authorized owner decisions and measured maintenance outcomes.

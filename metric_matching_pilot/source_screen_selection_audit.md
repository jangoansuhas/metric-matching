## Source-independent policy assessment

The amendment changes the reviewer-capacity timing for **eligibility inventory and extraction coverage only**. It retains fixed hash order and commits, a contiguous screened prefix, the first two independently eligible projects, rejection/quarantine records, and a stop before the untouched tail. It explicitly bars pair comparisons, labels, relationship methods, executed metric values, outcome-driven replacement, and a pair draw in this phase. The fixed adapter is run only after selection when technically possible; build or syntax failure is a coverage result, never a reason to replace a selected project. An adjacent commit is an event-task condition, not a requirement for this within-revision pair screen. This is a coherent outcome-blind boundary, subject to the operational points below.

1. **Make the numeric-output counting rule mechanical before rank 1 is opened.** The freeze admits declared outputs and reproducibly identified aggregate-query outputs, but does not fully specify the raw-SQL extractor or the boundary between one output and several explicit filter/time/group variants. Use stable IDs from pinned file, declaration or query-output identity, and **explicit** scope; exclude ordinary projections and raw numeric columns without aggregate semantics. Do not multiply one declaration by possible runtime groupings. Keep aliases as metadata and keep derived, ratio, cumulative, templated, unsupported, and unresolved-numeric definitions visible. Two confirmed inspectable numeric outputs can establish the count threshold even while the full denominator is being inventoried. Conversely, reject for fewer than two only after a complete source screen establishes that unresolved candidates cannot change the threshold; otherwise quarantine the count decision and advance without calling the project ineligible. Complete the selected project's source-defined denominator after selection without making extraction ease a replacement criterion.
2. **Record independence as evidence, not a name inference.** Compare numeric repository IDs and documented fork/source/parent/template, submodule, copied-seed/dataset, and commit-family provenance against the four development families and previously screened selections. A template flag or a Rill-like name alone proves nothing. Quarantine an uncertain family/dataset link, including rank 3 if reached, before admission; keep the earlier eligible hash rank for a demonstrated shared family. An unresolved earlier row limits any assertion that the selected projects are the first two *truly* eligible across the prefix: state the selection relative to resolved decisions and retain the unresolved count.
3. **Separate eligibility counts from adapter reach.** The pinned adapter exports a commit, runs dbt dependencies and parse, then attempts `mf query --explain` for semantic-manifest metrics; it does not enumerate every possible declared measure or non-dbt aggregate output. Its generated-SQL numerator must therefore be paired with both the complete source-defined output denominator and an explicit adapter-target/attempt denominator. Record parse, dependency, unsupported-project, metric-time retry, and per-definition SQL-generation failures, tool versions, and material dependency/submodule SHAs. A failed run or incompatible project remains selected if its source screen passed. No generated SQL is a runtime numeric-value certification.
4. **Preserve the later gate.** Freeze and hash the selected projects' complete numeric-output inventories and unordered pair-ID frames, including unsupported definitions, before relationship methods. If completeness remains unresolved, report observed counts and missing coverage; do not replace the project or proceed as if its full pair frame were known. Staffing of two independent qualified reviewers and a distinct adjudicator still precedes the fixed pair draw, method scoring, and labels. An eligibility/extraction report alone cannot support accuracy, gold, or exact Recall@k claims.

These are prospective clarifications to apply uniformly; the present metadata cannot resolve them by examining candidate outcomes. No queued row has been admitted by this audit.

## Minimal selection ledger record schema

Use one dated, canonically serialized ledger with the following four parts. Store the final SHA-256 **outside** the hashed bytes (for example, in the report that publishes the ledger); a self-hash field cannot hash itself. Evidence locators may refer to pinned metadata or source files and their digests, but must contain no pair labels or predictions.

| Part | Required fields and meaning |
| --- | --- |
| `header` | `schema_version`, `created_at_utc`, `freeze_v1_sha256`, `presolve_v1_sha256`, `amendment_sha256`, `manifest_sha256`, `queue_sha256`, `adapter_sha256`, `target_selected: 2`. These identify the exact policy and inputs; the first two policy hashes refer to the archived pre-amendment bytes. |
| `screens[]` (one record per opened queue rank) | `rank`, `repository_id`, `project_key` (full pinned `owner/repo@40-hex-SHA`, copied from that queue row), `screened_at_utc`, `decision_at_utc`, `access` (`ok`/`unavailable`), `versioned_source` (`yes`/`no`/`unresolved`), `verdict` (`selected`/`rejected`/`unavailable`/`quarantined_unresolved`), `reason_code`, `independence` (`independent`/`related`/`unresolved`), optional `family_ref`, and `evidence[]` of typed pinned locators plus digest or recorded access failure. Record source paths examined and `source_file_count` (null when none inspected). `screen_inventory` holds `status` (`complete`/`partial`/`unavailable`), `exposed_observed`, `eligible_numeric_confirmed`, `numeric_unresolved_observed`, `known_ineligible_observed` (null where not established), and a source-linked stable-ID inventory locator and SHA-256 when produced. Complete counts partition `exposed_observed`; partial counts are observed coverage, not a complete denominator. Rejections and quarantines stay in this array, even when no source could be read. |
| `stop` | `decided_at_utc`, `screened_prefix_length`, `selected_ranks`, `unscreened_tail_count`, `reason` (`two_selected`/`queue_exhausted`). This fixes the replacement trace and the unopened suffix. |
| `adapter_runs[]` (after `stop`, selected ranks only) | `rank`, `project_key`, `attempted_at_utc` (null if not attempted), `status` (`not_attempted`/`success`/`partial`/`failed`/`not_applicable`), `reason_or_failure_class`, `final_inventory_status` (`complete`/`partial`), `source_definition_denominator` (full exposed count if complete; null otherwise), `observed_definition_count`, `final_inventory_locator`/`final_inventory_sha256`, `adapter_target_count`, `attempted_count`, `sql_generated_count`, `failure_counts_by_class`, `tool_versions`, and `artifact_locator`/`artifact_sha256` (null if none). Reconcile a per-definition outcome to **every observed** source inventory ID in the hashed coverage artifact, marking untargeted and unattempted definitions explicitly, so aggregate success cannot hide skips or failures. For a non-attempt, give the concrete reason rather than a zero-success interpretation. |

**Validation invariants.** `screens[i].rank == i + 1` for every record; every ID, key and SHA equals queue rank `i + 1`; ranks are unique and form exactly `1..screened_prefix_length`, with `unscreened_tail_count = 62 - screened_prefix_length`. Every `selected` record has confirmed public pinned versioned source, independent provenance and at least two confirmed inspectable numeric outputs, regardless of later extraction success. A count rejection requires a complete inventory and fewer than two eligible outputs after resolving candidates that could affect the threshold. Each rejected, unavailable, or quarantined row has evidence and a reason, and none is silently dropped. `selected_ranks` equals the selected screen ranks in order; stop at the second selection, or at rank 62 if fewer than two can be selected. No adapter or inventory-completion outcome changes a screen verdict or leads to a replacement. Hash a dated final ledger; preserve any later correction as an append-only, dated decision event tied to the original rank and prior ledger digest, never by rewriting the queue or original decision. Report unresolved earlier rows when describing the scope of a “first two” claim.

This schema records selection and extraction coverage only. It carries no pair IDs, pair relationships, method rankings, executed values, or human labels.
